The four key classes

static

DataKey::Admin

One entry for every caller. A write here serialises everything that reaches it.

subject-derived

DataKey::Balance(addr)

Different callers, different ledger entries. This is the goal state.

sequence-derived

DataKey::Job(id)

Looks parameterised. Isn't — minting id read and bumped a shared counter. The trap.

And one rule that fits no column: everything in instance() storage is a single ledger entry. A per-address key in instance storage is not parallel-safe, because the address never separated anything.
